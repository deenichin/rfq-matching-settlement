# Failure modes — complete listing

The full record behind `failure-modes.md`. Every race condition and partial failure the
system handles, grouped by hazard rather than one row per test: 72 tests cover 27 distinct
hazards, and the hazard is the useful unit. The tests that carry each hazard are named, so the
list can be checked against the suite.

`failure-modes.md` is the one-page summary — the hazards whose answer is not obvious, plus
what the system bounds rather than eliminates. Read that first; this is for checking the
claims.

Files are under `crates/`; `core/` is marked, everything else is in `runtime/tests/`.

## Races — two things at once, or an order the system does not control

| Hazard | What the system does | Tests |
|---|---|---|
| A claim expires part-way through a command, so a decision is taken against a stale total | Reclamation runs inline at the start of every command touching that account, before anything is decided; liveness is half-open, so a claim expiring at exactly the sampled instant is dead | `core/ledger::release_expired_reclaims_the_expired_prefix_and_leaves_the_total_equal_to_the_chain_sum`, `::a_claim_expiring_at_exactly_now_is_reclaimed_not_deferred`, `::free_normalises_before_answering`, `market::a_request_past_its_deadline_is_expired_by_derivation_and_admits_nothing` |
| Reclamation reaches capital already committed to a settling basket | Committed claims live on a different chain with no expiry field, so the traversal cannot reach them — no guard, an impossibility | `core/ledger::normalisation_cannot_reach_committed_capital`, `core/ledger_properties::committed_capital_survives_every_normalisation` |
| A rejection looks like a mutation because a claim died in between | Byte-identity is measured against the post-reclamation state, not the pre-command one | `market::the_same_rejection_with_an_expired_reservation_still_compares_equal` |
| A handle is held across a slot being freed and reissued to something else | Every slot carries a generation, checked on every dereference; a stale handle resolves to nothing rather than to the new occupant | `core/ledger::a_stale_claim_handle_from_a_freed_slot_is_rejected_by_generation_mismatch`, `core/slab::stale_handle_is_rejected_after_the_slot_is_reused`, `::capacity_is_never_exceeded_and_stale_handles_never_resolve`, `settlement::a_nonce_whose_generation_has_moved_on_names_nothing` |
| A quote or request slot is freed while capital still references it | Refused outright — an owner holding capital cannot be closed | `core/ledger::an_owner_holding_capital_cannot_be_closed_out_from_under_it`, `::a_request_holding_committed_capital_cannot_be_closed` |
| Arbitrary interleavings of reserve, release, commit and expiry | Invariants asserted after every operation over randomised sequences | `core/ledger_properties::invariants_1_and_2_hold_over_randomised_sequences` |
| Several clients submit at the same instant | One thread owns all state behind a bounded channel; every command lands once in channel order with a strictly increasing timestamp, and replaying the log rebuilds the same state byte for byte. Rejected commands are logged too, because they reclaimed capital | `single_writer::several_client_threads_submit_and_the_channel_serialises_them`, `::concurrent_clients_are_serialised_and_the_log_replays_exactly`, `::a_rejected_command_still_normalises_so_the_log_must_keep_it`, `::the_same_round_runs_on_the_shipping_clock` |
| Venue time and chain time disagree — a quote live by one, expired by the other | Each system holds its own clock; divergence is representable rather than assumed away, and settlement is judged by the chain's. The basket reverts whole and every claim returns to free | `harness::the_two_clocks_advance_independently`, `::custody_can_run_ahead_of_the_venue`, `::custody_holds_its_own_clock_instance`, `settlement::a_reverted_nonce_fails_the_settlement_and_returns_every_claim_to_free`, `custody::claim_coverage_is_a_cross_system_assertion_and_the_harness_can_break_it` |
| A withdrawal matures between the pre-flight balance check and the settlement itself | The pre-check has no correctness role. Settlement validates every leg against live balances inside the transaction and debits all or none | `custody::a_withdrawal_landing_between_the_pre_check_and_the_settle_reverts_the_whole_basket`, `::a_withdrawal_executed_before_the_accept_is_caught_by_the_pre_check` |
| A participant withdraws capital one of their own live claims has promised | Withdrawal delay must exceed the longest a quote or request can bind plus every chain-to-engine lag, so the claim always dies first. A venue configured otherwise refuses to start, and insufficient funds at settlement is thereby unreachable at zero lag | `custody::no_participant_can_withdraw_out_from_under_their_own_live_claim`, `::a_quote_admitted_just_before_a_withdrawal_must_die_before_it_executes`, `::a_venue_whose_timelock_does_not_cover_the_lag_terms_fails_to_start`, `settlement::insufficient_funds_at_settlement_is_unreachable_without_lag`, `core/config::the_claim_window_is_a_maximum_over_both_sides_not_the_quote_side_alone`, `::a_lag_term_alone_can_violate_the_timelock_inequality`, `::a_horizon_that_does_not_cover_request_ttl_plus_settling_time_fails_to_start`, `harness::the_harness_refuses_to_start_on_a_configuration_that_fails_its_assertions` |
| A pending withdrawal silently kills every basket in flight — last look reintroduced through custody | Admission reads availability (forward-looking, never lends against money leaving); settlement reads balance (is it here now). Execution at maturity consults nothing else — no quote, no escrow | `custody::a_pending_withdrawal_does_not_kill_a_basket_already_in_flight`, `::requesting_a_withdrawal_drops_availability_immediately_and_the_balance_not_at_all`, `::execution_occurs_at_exactly_the_delay_and_consults_nothing_else`, `::a_withdrawal_executes_at_maturity_even_with_capital_locked_in_escrow` |
| A settlement is submitted twice, or its acknowledgement is lost and the engine retries after inclusion | The chain reports the fate of the nonce, not of the submission. A retry bouncing off its own consumed nonce is evidence the original **succeeded**, and the nonce still reads settled | `settlement::a_retry_after_inclusion_reverts_on_its_own_nonce_and_that_is_not_a_failure`, `::a_retry_before_inclusion_is_applied_exactly_once`, `::a_retry_after_a_revert_finds_reverted_and_a_retry_after_a_settle_finds_settled`, `custody::a_resubmitted_bundle_bounces_off_its_own_nonce` |
| Chain events are delivered twice, after a restart or a rewound cursor | Keyed on transaction hash **and** log index, independent of the cursor — one transaction emitting several logs is ordinary, and the hash alone would drop all but the first. Re-settling an escrow is a no-op | `indexer::rewinding_the_cursor_changes_nothing_but_forgetting_the_dedup_set_delivers_twice`, `::one_transaction_with_several_logs_is_deduplicated_per_log_index`, `resolution::settling_the_same_escrow_twice_is_a_no_op` |
| A block carrying a resolution is orphaned and replaced by one with the opposite outcome | Entries are delivered only once buried under a confirmation depth, so the orphan is never seen. Had it been, that outcome would be locked in permanently, since outcomes cannot be revised. A chain shallower than the depth delivers nothing rather than everything | `indexer::a_reorg_below_the_confirmation_depth_is_never_seen_by_the_engine`, `::nothing_is_delivered_from_a_chain_shallower_than_the_confirmation_depth` |
| A payout request arrives before the resolution authorising it | The payout re-derives the outcome as it pays: refused with no outcome, succeeds once one exists. Safety does not depend on delivery order, and nothing is queued on the engine's behalf | `indexer::a_settlement_request_arriving_before_its_resolution_is_refused_and_works_afterwards`, `resolution::an_escrow_on_a_contract_in_progress_cannot_be_settled_and_nothing_moves` |
| Two quotes arrive at the same price, in an order the venue does not control | Earlier arrival wins, which denies any gain from spamming identical quotes | `market::the_earlier_arrival_wins_a_tie` |
| The quotes change between being shown to the requester and being accepted | The acceptance carries the prices the requester saw; selection re-runs at that moment. Better fills silently, worse rejects and changes nothing, and an expired best publishes nothing and fails safe | `market::a_better_quote_arriving_before_the_accept_fills_at_the_better_price`, `::a_worse_selection_at_accept_time_rejects_and_mutates_nothing`, `::an_expiring_best_quote_publishes_nothing_and_the_stale_view_fails_safe` |
| A request is opened on a contract already too close to its event date to resolve normally | Admission refuses on horizon, so an escrow can never form on a contract whose grace has elapsed | `market::admission_refuses_a_deadline_beyond_the_ttl_and_a_contract_too_near_its_event` |
| The oracle changes its answer, retracts it, or is contested while payouts are in progress | Status moves forward only and a final answer can never be replaced. Contesting cannot buy an unwind: a contested contract never times out and only the escalation authority ends it. Silence past the grace period unwinds to void, returning each side its own contribution | `resolution::final_is_immutable_and_the_failure_it_prevents_is_invisible_to_every_invariant`, `::a_final_contract_refuses_every_later_report`, `::the_oracle_cannot_walk_its_status_backwards`, `::an_oracle_parked_in_progress_never_times_out_into_void`, `::a_contested_contract_ends_only_when_the_escalation_authority_rules`, `::a_silent_oracle_past_the_grace_period_returns_each_side_its_own_contribution` |

## Partial failures — something completes for part of the system and not the rest

| Hazard | What the system does | Tests |
|---|---|---|
| One leg of a three-leg basket cannot be filled after the others matched | Selection happens in a phase that mutates nothing. The whole request aborts before any capital moves: ledger unchanged, no event emitted, other legs still active, request still open. There is no partial-fill state and nothing to unwind | `market::leg_two_of_three_has_no_eligible_quote_and_the_whole_request_aborts` |
| One maker wins several legs and can afford any one but not all together | Admission refuses the second quote: the ledger maintains free ≥ reserved + committed and cannot be talked out of it, so a maker never holds claims they cannot cover and a bundle they cannot afford never forms. Custody also sums debits per account and checks once against the total, but that path is unreachable through this engine in v1 and correspondingly unverified — replacing it with per-leg checking passes the whole suite. It is defence-in-depth for a v2 where a lagging mirror can make admission wrong | `custody::a_settlement_debits_each_account_once_for_every_leg_it_wins` (exercises the admission half) |
| A settlement is submitted and no answer comes back | Nothing is released. Both sides stay committed and the engine keeps asking, because every guess is wrong: releasing lets the same capital be committed twice, recording an escrow that never formed invents money. The deadline alerts and releases nothing | `settlement::an_unknown_nonce_holds_every_claim_and_commits_nothing_twice`, `::reaching_the_settling_deadline_alerts_and_releases_nothing`, `::a_committed_claim_names_a_consumed_quote_at_every_step_of_settling` |
| A settlement resolves and the engine has not yet learned which way | The terminal nonce answer discharges the claims — to escrow if it settled, to free if it reverted. This closes the coverage window below | `settlement::a_settled_nonce_moves_the_request_to_escrowed_and_discharges_the_claims`, `::a_reverted_nonce_fails_the_settlement_and_returns_every_claim_to_free` |
| A claim is momentarily neither reserved nor committed | The two chains are swapped in one step; there is no such bucket in the money model | `core/ledger::commit_moves_a_claim_between_chains_in_one_step` |
| The engine's view of balances is half-current | For deposits the engine's number is low until an entry is confirmed, so it refuses quotes it could have allowed — a liveness cost only. For withdrawals it runs the other way: availability drops the moment one is requested, and until the indexer delivers that entry the engine can admit a quote against money already leaving. The timelock closes that, not the mirror — indexer lag is a term in the withdrawal-delay inequality, so a quote admitted while the engine was over-optimistic expires before the money can move | `indexer::a_lagging_indexer_leaves_the_engine_stale_but_never_wrong` (deposit direction only) |
| The process publishing events dies or falls behind | The engine is never blocked by a reader — a full buffer drops its oldest entry, and sequence numbers are assigned to dropped events so a gap is computable rather than invisible. The engine keeps applying; the state machine is authoritative and the stream is best-effort | `event_ring::a_full_ring_evicts_its_oldest_entry_rather_than_refusing_the_writer`, `::sequence_numbers_are_assigned_to_dropped_events_too_so_gaps_are_visible`, `single_writer::the_engine_keeps_applying_after_the_publisher_dies` |
| A slab or the event buffer fills mid-command | Rejection naming which resource, never reallocation; buffer headroom is checked before the commit phase, which cannot fail. Per-leg quote limits keep the commit-phase event count bounded by configuration rather than by traffic | `core/ledger::slab_exhaustion_is_a_rejection_naming_the_slab`, `core/slab::exhaustion_is_a_rejection_not_a_reallocation`, `::capacity_is_never_exceeded_and_stale_handles_never_resolve`, `market::a_leg_admits_at_most_max_quotes_per_leg_live_quotes` |
